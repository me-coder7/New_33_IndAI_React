## Publishing the shared plan once, then starting member work

The ownership/commit-planning files themselves are coordinated by the authorized integrator. They are not five new feature contributions. Commit that actual shared planning work once under its real integrator identity, then fast-forward the existing clean member branches to that shared-plan commit so the scripts are available. No additional member commits are generated by a fast-forward.

```powershell
git switch team-module-ownership
# The current pending ownership draft must be preserved and reviewed.

git commit -m 'docs(team): prepare actor file lists and genuine commit workflow'
# Once committed, each still-clean member branch can receive the shared plan:
git switch feature/learner-jeswanth
git merge --ff-only team-module-ownership
# Repeat the same fast-forward for the other four existing clean member branches.
# If a member branch already has commits, inspect it instead of resetting/replacing it.
```

Each member then performs a real feature/fix, reviews their exact diff, runs their tests and authorizes the resulting commit. Existing module files are already tracked; pushing file names alone does not create author credit.
